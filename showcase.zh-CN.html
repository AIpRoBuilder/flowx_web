02 / 更多构建

不同的任务。
同样的循环

每个案例都会留下图、版本化节点、测试和可运行的服务；打开源码可以看到确切的产物

快速开始 / MCP

工单分诊

识别工单类别、设置优先级，并起草结构化回复。README 从意图、契约任务一路走到完整构建。

create_workflow("ticket-triage")
begin_build(intent=...)
  → requirement
  → workflow.json
  → classify + test
  → prioritize + test
  → draft_reply + test

SDK / 演进

只改一个节点

examples/sdk_evolve.py 只修改一个节点，冻结图拓扑，并复用输入未变化的节点。

begin_build(
  workflow_id,
  intent="change the reply tone",
  target="draft_reply",
)
reused: classify, prioritize

SDK / 修复

只修真正失败的部分

examples/sdk_guided_repair.py 带一个被拒绝的节点走完检查结果、修复任务和第二次提交。

findings: [
  { rule_id, line, message, remediation }
]
→ repair task (attempt 2)
→ submit_task(...)
→ published v2

媒体 / FLOWX 1.0.3

提示词、图片和视频卡片

生成的节点可以返回媒体卡片。媒体工具包提供 Provider 辅助、Pillow、FFmpeg，以及零成本节点测试的 dry-run 模式。

node output:
  cards: [
    { type: "prompt", ... },
    { type: "image", ... },
    { type: "video", ... }
  ]

A2A / 对等 AGENT

委托一次构建

另一个 Agent 可以通过非流式适配器发起构建。契约任务未完成时，A2A 任务为 input-required；在同一个任务 ID 上作答。

flowx-a2a --host 127.0.0.1 --port 8001

POST /a2a  message/send
→ input-required
→ { task_id, artifacts }
阅读 A2A 协议 ↗
内部机制 / 架构

两个实体，一个运行时

构建器检查产物并渲染服务；服务管理器驱动步骤并返回证据。生成的 FastAPI 运行时位于你的 UI 下方。

intent → requirement → graph
→ nodes + tests → entrypoint
→ FastAPI + ag_ui_workflow
→ run journal + evidence
