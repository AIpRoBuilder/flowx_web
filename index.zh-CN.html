03 / QUICKSTART

从这里开始，
构建你的第一个流程。

安装 FlowX 后，选择 MCP 连接你的 Agent，或直接使用 Python SDK。需要 Python 3.10+ 和已配置的 LLM 服务。

01 / MCP

连接你的 Agent

在支持 MCP 的客户端中注册本地服务。将路径替换为实际的虚拟环境和配置目录；Windows 请使用对应的 Scripts 可执行文件。

mcp.json
{
  "mcpServers": {
    "flowx": {
      "command": "/absolute/path/to/venv/bin/flowx-mcp",
      "env": {
        "FLOWX_CONFIG_ROOT": "/absolute/path/to/config"
      }
    }
  }
}

在配置目录的 .env 中设置 FLOWX_LLM_PROVIDER、FLOWX_LLM_MODEL、FLOWX_LLM_API_KEY 和 FLOWX_DEFAULT_WORKSPACE；不要将密钥提交到代码仓库。

02 / PYTHON SDK

用代码构建工作流

配置好 LLM 后，使用 SDK 从自然语言构建工作流，并检查生成的产物。

build_workflow.py
from flowx_sdk import FlowXClient

with FlowXClient(workspace="./workflows") as flowx:
    result = flowx.build_workflow(
        "创建一个总结文档的工作流。",
        await_repair_input=False,
    ).raise_for_failure()

    print("Workflow:", result.workflow_id)
    print("Artifacts:", flowx.artifacts(result.workflow_id))

在运行 SDK 的环境中配置模型变量。构建期间可能执行节点测试；运行生成的服务前，请审阅产物和代码。

需要配置细节？查看完整安装文档 ↗

06 / GOOD TO KNOW

常见问题.

关于 FlowX，还有什么想了解的？

查看完整文档 ↗
FlowX 是一个可视化工作流编辑器吗？+

不是。FlowX 是生成式工作流层，不自带用户界面。你的 Agent 或应用负责交互和展示，FlowX 负责生成、运行和演进背后的流程。

工作流生成后保存在哪里？+

工作流产物保存在配置的本地工作区中，包括工作流图、节点代码和后端入口，可供检查和后续演进。

节点测试没有通过怎么办？+

节点构建包含审计、测试和有限次数的修复。需要时可以提供修改指导；仍未通过的节点不会发布。

FlowX 支持哪些接入方式？+

支持本地 stdio MCP、Python SDK 和 A2A 适配器。其中 A2A 当前用于非流式工作流构建。
