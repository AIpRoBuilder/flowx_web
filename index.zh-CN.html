02 / 你得到什么

不只是回答。
构建可执行的流程

FlowX 是 Agent 背后的执行层：发放契约、检查返回结果，只保留真正通过的内容

✳
01 / 契约

契约，而非提示词

每个构建步骤返回指令、规则、上下文和产物槽位；由宿主 Agent 编写代码，而不是猜一个结果

⌁
02 / 检查

审计并测试每个节点

审计器与 pytest 共同检查每个节点；失败会返回行号、修复建议和有限次数的修复任务

↻
03 / 版本

只发布通过的内容

通过的产物成为版本化节点；未通过的节点不会发布，其下游节点会被标记为阻塞

⌘
04 / 演进

不重建也能演进

可以只修改一个节点或整张图；未改变的节点直接复用，工作流保留完整历史

03 / 工作原理

九个步骤。
一次可检查的构建

从任意 Harness 到可运行的服务：每一步都会留下产物、检查结果或可阅读的日志

STEP 01

任意 Harness

在 Claude Code、Codex、Hermes Agent、DeepSeek Harness，或你自己的 Python / A2A Agent 中，通过 FlowX skill 或本地 MCP 服务接入。

CLAUDE CODECODEXHERMESDEEPSEEK HARNESS
HARNESS → FLOWXLOCAL STDIO
claude code   codex   hermes   deepseek harness
       \         |        |             /
        flowx skill  ·  flowx-mcp  ·  flowx_sdk
                     |
              local workspace
STEP 02

描述意图

告诉 Agent 工作流要完成什么。Agent 分配工作流并打开构建修订，FlowX 选择阶段并发出第一批契约。

自然语言CREATE_WORKFLOWBEGIN_BUILD
INTENTAGENT
› Use flowx to build a workflow.

  A support ticket comes in. Classify its category,
  assign a priority, and draft a reply as
  structured output.

create_workflow(name="ticket-triage")
→ workflow_id: ticket-triage
STEP 03

接收契约

begin_build 返回 next_tasks：每个产物都有契约，包含指令、规则、schema、上下文和提交槽位。Agent 不需要猜结构。

契约SCHEMA产物槽位
NEXT_TASKSREQUIREMENT
{
  "task": "requirement",
  "contract": { "rules": [...], "schema": {...} },
  "context": {},
  "submit": { "slots": ["requirement"] }
}
STEP 04

编写产物

编码 Agent 先写需求，再写工作流图，然后为每个节点编写代码和测试。相互独立的节点会同时开放。

需求图代码 + 测试
WORKSPACETICKET-TRIAGE
workflows/ticket-triage/
├── requirement.md
├── workflow.json
├── nodes/
│   ├── classify.py      + test_classify.py
│   ├── prioritize.py    + test_prioritize.py
│   └── draft_reply.py   + test_draft_reply.py
└── build/events.jsonl
STEP 05

审计返回结果

FlowX 用审计器检查每个产物。拒绝是具体的：规则、消息、行号和修复建议，Agent 可以只修复真正失败的部分。

确定性规则FINDINGS修复建议
AUDITFINDINGS
AUDIT  graph        PASS
AUDIT  classify     FAIL
  rule_id:  node.schema-output
  line:     42
  message:  "category" is not validated
  remediation:
    validate the field against the declared enum
STEP 06

用 pytest 测试

每个节点的测试在本地运行。失败会带着测试输出返回修复任务；修复次数有上限，构建不会无限循环。

PYTEST修复任务MAX_ATTEMPTS
PYTESTNODE: CLASSIFY
$ pytest nodes/test_classify.py
FAILED test_classify_rejects_unknown_category
1 failed, 4 passed

→ repair task opened (attempt 2 / 3)
STEP 07

发布版本

通过的节点带着版本发布。仍然失败的节点不会发布，其下游节点被标记为阻塞；get_build_state 和日志会显示构建状态。

版本化节点构建状态构建日志
GET_BUILD_STATEBUILDING
status: building
nodes:
  classify      published v2
  prioritize    published v1
  draft_reply   repair (attempt 2/3)
entrypoint: waiting
STEP 08

运行服务

run_service 渲染并启动 FastAPI 后端；run_step 输入数据，reset_session 清理暂停的会话，get_evidence 返回运行日志和服务日志尾部。

FASTAPIRUN_STEPEVIDENCE
SERVICERUNNING
run_service("ticket-triage")
  http://127.0.0.1:8000

run_step("ticket-triage", "classify", {...})
  completed · 3 cards
get_evidence("ticket-triage")
  runs/latest.json + service.log
STEP 09

演进与复用

begin_evolve 可以在冻结拓扑的情况下修改一个节点，也可以修改整张图。输入未变化的节点全部复用，已发布版本继续可用。

BEGIN_EVOLVE节点或图复用
EVOLVEDRAFT_REPLY
begin_evolve("ticket-triage",
  intent="Escalate urgent tickets",
  scope="node", node="draft_reply")

reused    classify v2, prioritize v1
rewritten draft_reply v2
published draft_reply v2

04 / 快速开始

本地安装。
构建第一个工作流

FlowX 运行在 Python 3.10+ 上，内部不需要模型密钥。安装后通过 MCP 或 SDK 连接，让 Agent 编写产物

macOS / LINUX · PIP
git clone https://github.com/AIpRoBuilder/FlowX.git
cd FlowX
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .

FlowX 内部不需要模型密钥；Provider 和媒体变量只用于你生成的工作流。Windows 请激活 .venv\Scripts\activate 并使用 Scripts 目录下的可执行文件。

01 / MCP

连接你的 Agent

在支持 MCP 的客户端中注册本地 stdio 服务；请使用绝对路径，MCP 主机可能不会继承 Shell 的 PATH

mcp.json
{
  "mcpServers": {
    "flowx": {
      "command": "/absolute/path/to/venv/bin/flowx-mcp",
      "env": {
        "FLOWX_DEFAULT_WORKSPACE": "/absolute/path/to/flowx_workspaces"
      }
    }
  }
}

FLOWX_CONFIG_ROOT 可让已安装的 flowx-mcp 找到仓库外的 .env。工作流凭据放在进程环境或服务自己的 .env 中；不要提交密钥

02 / PYTHON SDK

用代码构建工作流

FlowXClient 暴露同一套协议；build() 用你提供的函数回答每个契约任务

build_workflow.py
from flowx_sdk import FlowXClient

def solve(task: dict) -> dict:
    return my_agent.write(task)

with FlowXClient(workspace="./workflows") as flowx:
    workflow_id = flowx.create_workflow("ticket-triage")
    state = flowx.build(
        workflow_id,
        "Categorize and prioritize support tickets.",
        solve,
    )
    assert state["status"] == "completed", state["errors"]
    print(flowx.run_service(workflow_id))

构建期间会在本地执行节点测试，运行服务前请审阅生成的代码；使用服务时保持客户端开启

08 / 值得了解

常见问题

关于 FlowX，还有什么想了解的？

阅读完整手册 ↗
FlowX 是一个可视化工作流编辑器吗？+

不是，FlowX 是工作流构建器与服务管理器，不自带用户界面；你的 Agent 或应用负责交互和展示，FlowX 负责构建、检查、版本化和运行背后的流程

FlowX 会调用模型吗？+

不会。FlowX 内部没有 LLM；它把每个产物的契约交给编码 Agent，并审计返回结果。只有你生成的工作流在调用模型或媒体服务时，才需要对应的 Provider 密钥

工作流生成后保存在哪里？+

产物保存在 workspace/workflows/<workflow_id> 下，包括需求、工作流图、版本化节点代码与测试、入口文件和构建日志

节点测试没有通过怎么办？+

审计器和 pytest 会返回行号、修复建议和修复任务，修复次数有上限。仍未通过的节点不会发布，其下游节点会被标记为阻塞

FlowX 支持哪些接入方式？+

支持本地 stdio MCP、Python SDK、A2A 适配器，以及面向 Claude Code、Codex 和 Hermes Agent 的 skill；DeepSeek Harness 还可安装只读查看器插件。A2A 当前用于非流式工作流构建
