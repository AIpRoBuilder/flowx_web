02 / THE INTERFACES

Same protocol.
Three doorways

Pick the transport that fits the host; the builder, gates, versions, and service manager stay the same

01 / MCP

Agent client

Register the local stdio server; MCP hosts may not inherit your shell's PATH, so use absolute paths.

mcp.json
{
  "mcpServers": {
    "flowx": {
      "command": "/absolute/path/to/venv/bin/flowx-mcp",
      "env": {
        "FLOWX_DEFAULT_WORKSPACE": "/absolute/path/to/flowx_workspaces"
      }
    }
  }
}

Start the server manually with flowx-mcp or flowx-mcp --verbose when you want to inspect the entry point.

02 / PYTHON SDK

Your application

FlowXClient exposes the same protocol, and build() answers every task with a function you provide.

sdk.py
from flowx_sdk import FlowXClient

def solve(task: dict) -> dict:
    return my_agent.write(task)

with FlowXClient(workspace="./workflows") as flowx:
    workflow_id = flowx.create_workflow("ticket-triage")
    state = flowx.build(workflow_id, "Categorize support tickets.", solve)
    assert state["status"] == "completed", state["errors"]
    print(flowx.run_service(workflow_id))

Keep the client open while using a started service; exiting the with block stops services it started.

✦

A2A, without a transport rewrite — another agent can delegate a build through the non-streaming adapter: flowx-a2a --host 127.0.0.1 --port 8001. While contract tasks are open the task is input-required.
