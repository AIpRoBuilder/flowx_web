QUICKSTART / MCP

Ticket triage

Classify a support ticket, assign a priority, and draft a reply as structured output. The README walks from intent to contract tasks to a finished build.

create_workflow("ticket-triage")
begin_build(intent=...)
  → requirement
  → workflow.json
  → classify + test
  → prioritize + test
  → draft_reply + test

SDK / EVOLUTION

Change one node

examples/sdk_evolve.py targets a single node, keeps the graph topology frozen, and reuses the nodes whose inputs did not change.

begin_build(
  workflow_id,
  intent="change the reply tone",
  target="draft_reply",
)
reused: classify, prioritize

SDK / REPAIR

Fix exactly what failed

examples/sdk_guided_repair.py walks a rejected node through findings, a repair task, and a second submission that passes.

findings: [
  { rule_id, line, message, remediation }
]
→ repair task (attempt 2)
→ submit_task(...)
→ published v2

MEDIA / FLOWX 1.0.3

Prompt, image, and video cards

A2A / PEER AGENT

Delegate a build

Another agent can start a build through the non-streaming adapter. While contract tasks are open, the A2A task is input-required; answer on the same task id.

flowx-a2a --host 127.0.0.1 --port 8001

POST /a2a  message/send
→ input-required
→ { task_id, artifacts }

UNDER THE HOOD / ARCHITECTURE

Two entities, one runtime

The builder gates artifacts and renders the service; the service manager runs steps and returns evidence. The generated FastAPI runtime sits underneath your UI.

intent → requirement → graph
→ nodes + tests → entrypoint
→ FastAPI + ag_ui_workflow
→ run journal + evidence
