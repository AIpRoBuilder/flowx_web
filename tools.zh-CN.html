FLOWX / 工具面

22 个工具。
三种接入方式。一个工作流。

MCP 工具面覆盖完整循环：分配工作流、接收契约、提交产物、观察检查、运行服务，并演进通过的内容。SDK 和 A2A 适配器暴露同一套协议。

02 / 接入方式

同一套协议。
三个入口

选择适合宿主的传输方式；构建器、检查、版本和服务管理器保持不变

01 / MCP

Agent 客户端

注册本地 stdio 服务；MCP 主机可能不会继承 Shell 的 PATH，请使用绝对路径。

mcp.json
{
  "mcpServers": {
    "flowx": {
      "command": "/absolute/path/to/venv/bin/flowx-mcp",
      "env": {
        "FLOWX_DEFAULT_WORKSPACE": "/absolute/path/to/flowx_workspaces"
      }
    }
  }
}

需要检查入口时，可以手动运行 flowx-mcp 或 flowx-mcp --verbose。

02 / PYTHON SDK

你的应用

FlowXClient 暴露同一套协议，build() 用你提供的函数回答每个任务。

sdk.py
from flowx_sdk import FlowXClient

def solve(task: dict) -> dict:
    return my_agent.write(task)

with FlowXClient(workspace="./workflows") as flowx:
    workflow_id = flowx.create_workflow("ticket-triage")
    state = flowx.build(workflow_id, "Categorize support tickets.", solve)
    assert state["status"] == "completed", state["errors"]
    print(flowx.run_service(workflow_id))

使用服务时保持客户端开启；退出 with 块会停止它启动的服务。

✦

A2A，无需重写传输层 — 另一个 Agent 可以通过非流式适配器委托构建：flowx-a2a --host 127.0.0.1 --port 8001。契约任务未完成时，任务状态为 input-required。
